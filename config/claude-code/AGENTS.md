# General

- Do not use emojis, smart quotes, em dashes.
- Keep replies short and direct. Expand only when asked.
- Always check latest documentation before responding or writing any code.
- Only give recommendations backed by official documentation, and cite the source for each one.
- If official documentation does not cover something, say so explicitly. Do not fill the gap with your own opinions or invented names presented as recommendations.
- Use IDE capabilities, plugins, LSPs as much as possible.
- Check current date to get up to date information on libraries, APIs and references.
- No workarounds, hacks or downgrades allowed.
- Do not over abtract.
- Keep code simple, as per best practices and do not reinvent the wheel.
- Never downgrade versions.
- Do not assume anything, always check before doing anything.
- Always prefer first party, standard library over third party stuff made by one guy in GitHub.
- No comments allowed in code, except for docstrings.
- Check IDE diagnostics after writing code and fix if any issues have been identified.

# Flutter / Dart / Mobile

- Only use first party packages: the Flutter and Dart SDKs, and pub.dev packages whose verified publisher is Google owned (for example flutter.dev, dart.dev, google.dev, firebase.google.com). Check the publisher on pub.dev before using a package.
- Never suggest, recommend, compare or mention third party packages, not even as alternatives or trade-offs.
- If no first party option exists, say so and stop. Do not offer a third party one instead.

# Plugins and MCP

- Only use official plugins, made by Anthropic or by the vendor of the tool itself. No third party or individual maintainer plugins, even when they are listed in Anthropic's marketplace. Check the plugin's author and repository owner before recommending it.
- If a tool has an official plugin, use the plugin. No hand-added MCP servers, copied skills, or claude.ai connectors for anything a plugin already covers.
